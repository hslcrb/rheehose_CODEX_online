# NTC (New Technology Compiler)

NTC는 **"GCC를 대체할 수 있는 차세대 컴파일러"**를 목표로 설계된 프로젝트입니다.

이 저장소의 구현은 단번에 GCC 전체를 100% 재구현하는 완성형이 아니라, 다음 특성을 먼저 확보하는 **실전형 부트스트랩 버전**입니다.

- GCC 스타일 CLI 호환 (`-c`, `-S`, `-E`, `-O*`, `-g`, `-I`, `-D`, `-L`, `-l`, `-std`, `-W*`)
- 멀티 소스 병렬 컴파일
- 내용 해시 기반 오브젝트 캐시(중복 컴파일 최소화)
- 향후 백엔드 교체를 위한 파이프라인 분리 구조

## 왜 이 구조인가?

GCC를 “완전 대체”하려면 현실적으로 다음이 필요합니다.

1. C/C++/Fortran 등 언어 프런트엔드
2. 최적화 파이프라인(SSA, IPO/LTO, 벡터화, PGO)
3. 타겟별 코드 생성기
4. 디버거/링커/빌드시스템과의 완전 호환

한 번에 구현하기 어렵기 때문에, 이 프로젝트는 먼저 **드롭인 가능한 드라이버 + 캐시 + 병렬화**를 제공하고,
프런트엔드/백엔드를 점진적으로 대체하도록 설계했습니다.

## 빠른 시작

```bash
python3 -m ntc --help
python3 -m ntc hello.c -O2 -c -o hello.o
python3 -m ntc a.c b.c -O3 -o app
```

기본적으로 내부적으로 `clang` 또는 `gcc`를 감지해 사용합니다.
(둘 다 없으면 오류를 반환)

## 설계 개요

- `ntc/driver.py`: CLI 파싱 및 실행 조정
- `ntc/compiler.py`: 컴파일/링크 실행기
- `ntc/cache.py`: 해시 기반 캐시 관리
- `ntc/toolchain.py`: 호스트 툴체인(clang/gcc) 탐색
- `ntc/models.py`: 빌드 요청/결과 데이터 모델

## 로드맵 (GCC 대체를 위한 단계)

1. **현 단계**: GCC 호환 드라이버 + 캐시 + 병렬화
2. NTC IR 정의 및 프런트엔드(C subset)
3. SSA 최적화 패스군 구현
4. LLVM/GCC 의존도 제거를 위한 독립 백엔드 도입
5. GCC 테스트 스위트 호환성/성능 검증

## 주의

이 버전은 GCC를 완전히 대체하지는 않지만,
**대체를 위한 현실적인 출발점(속도/구조/호환성 기반)**을 제공합니다.
